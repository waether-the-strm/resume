## What happened

- The board now holds the plan to `v2.0.0` and the milestones after it: 41 issues, each with a
  phase, a horizon and an owner type (Delegate, Lead, Jan). 21 are delegable, 10 stay with the lead
  session, 10 are decisions or checks only Jan can make.
- This reverses an earlier rule on purpose. The first session opened an issue only for work that
  would not be finished in that session. With several agents working, the plan has to exist as
  issues before anyone starts, so the rule now applies only to work the lead session does itself.
- Wrote `AGENTS.md`: the contract for any agent that takes a delegable issue. Base branch, scope,
  the four commands, evidence, and what is not theirs to change: copy, token values, decisions,
  dependencies. Added a pull request template that asks what was not verified.
- Splitting the plan exposed its real bottleneck. The engine, the scenes and the navigation are
  ports of a private prototype. An agent that works only in this repository cannot see it, so phases
  4 to 6 cannot be delegated until the spec is here (#15).

- First delegated batch, five issues to Cursor running Grok, each in its own worktree, with a
  hand-off file per pull request. Four merged the same day (#55 phone fit, #58 `/cv`, #59 font, #54
  site basics); the fifth (#62 Playwright) is in its second round. Reports were good: measured
  numbers, a list of what was not verified, and the decisions the agent made alone.
- What review caught. A 404 page that announced itself as a localized document. A test that pinned
  exact file sizes. And a false lead: local and CI results disagreed on the phone fit, and the agent
  suspected the platform. The cause was a branch cut before the fix it depended on; CI tests the
  merge with the base, the local run did not. Agents now rebase before they measure.
- What the agents caught. Unknown URLs get the host's bare `Not found` instead of the 404 page, and
  hashed assets are served without a long cache (#57). Dropping the font's unused cursive axis saved
  644 bytes: the weight is in the other axes and in the glyph count.
- The lead session wrote the engine's stop table, map, URL contract and store (#56), tested against
  values produced by the prototype's own functions.
- The spec moved into the repository (`docs/spec`), `rebuild` became the default branch, and the
  milestones were rebuilt as a roadmap with dates.

- Second batch to Cursor: six of eight merged the same day. `phases`, `settle`, `sound`, the
  preferences store, accessibility scans, and a deeper font subset: 613 KB down to one file of 49
  KB. `settle` and `phases` matched the prototype line by line and needed no changes.
- What review caught in the second batch. The view-transition runner was tested against a fake that
  ran the update synchronously; the real API runs it a frame later, and with real timing two changes
  in one turn would have been applied in the wrong order. A second round fixed the order; a third is
  making sure a change is applied even when the transition fails to start.
- What I got wrong. I told Jan nothing but the scroll hint used the font's slant axis. That was true
  of the prototype, not of the product: `/cv` used italics, and after the axis went the browser
  slanted them itself. The agent reported it. Jan ruled out faked letterforms; `/cv` is upright for
  now and `font-synthesis: none` is in the base.
- Jan's queue got its own shape on the board: a kind of work, a timebox and a target day on every
  issue that needs him.

## Decided (by Jan)

- The prototype and its notes may be published here; whatever a task needs may be published.
  [ADR 0008](../adr/0008-spec-in-the-repository.md)
- The phone scroll hint will be visual, not a line of casual italic text. The font drops the casual
  and slant axes (#60).
- `rebuild` is the default branch, so pull requests link to and close their issues.
- The roadmap: the prototype recreated, then the domain, then content and case studies, then warmth,
  then AI on design tokens. The domain comes before the content so the new design reaches strm.dev
  as early as possible.

- No letters slanted or emboldened by the browser, anywhere (#74).
- Load ahead of need: fetch what the next page needs when the reader shows intent. Real italics come
  back as a separate font file that only `/cv` downloads (#75).
- Words with roles is accepted (ADR 0007), with one change: a span per word only in the message, one
  span per marked run everywhere else (#78).
- A case study is a short article: the character of the work, his involvement, the curiosities. He
  writes them in a session of their own (#42).
- The lead session keeps judgement and gives the rest away: independent tasks to Cursor, simple
  steps to cheaper subagents.

# Third session, the same day

## Planned

Review what Cursor handed over, then the lead session's own work from NOW: the narrative content,
the adapter, the first scenes.

## What happened

- **Narrative content as data** (#22, #80). Five collections; the track and the structure notes are
  one file for every language, the words are per locale. A stop without a name, a name without a
  stop, and a token strm-ui does not define each fail the build.
- **The tour** (#87, refs #30). `scenes.ts` in the engine orders a scene change; the adapter writes
  the scene, its progress and the guide's step; the skins are CSS on `--t`. Fourteen Playwright
  tests, in both languages.
- **Reviewed and merged from Cursor:** #66 transitions (third round), #81 a span per word only in
  the message, #83 the key registry, #84 release preparation, #85 prefetch and the italic face.
- **The briefing rule** (#82): every agent opens a batch of work by telling Jan what, why now, what
  to expect, and how it fits.

## What went wrong, and what it taught

- The skins first lost to the page's own scoped styles: an Astro scoped rule carries an extra
  attribute, so a global rule of the same shape is weaker. Every rule of the tour now starts with
  `[data-tour]`, which also states what it is: a layer.
- The existing Playwright specs assumed the page at rest. With the tour they would have tested a
  page in motion. They now ask for reduced motion, which is what "the finished page" means.
- Two delegated pull requests could not meet their "Done when" because it depended on the adapter
  (#83: scenario G4). The issue should have been split before it was delegated.
- Pull requests written before the tour landed measure a page that has since changed (#86). A budget
  set from "the first measurement" has to be set again after a change this size.

## Decided

- By Jan: the briefing at the start of every batch, for every agent.
- By the lead session, for Jan to confirm: ADR 0009, proposed. The split of the stops into geometry
  and words follows ADR 0006 and has no record of its own.

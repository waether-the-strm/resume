## What happened

- Read the prototype's brief, test scenarios and scroll model, and the v1 site: two content pages
  (home and `/cv`), a PDF, deploy to GitHub Pages on a `v*.*.*` tag.
- Checked current versions instead of trusting memory. Astro is at 7.4 (v1 runs 4.13). What that
  changes for a new project: Node 22.23 or newer and even majors only, content collections defined
  in `src/content.config.ts` with loaders, Zod 4 from `astro/zod`, a stricter compiler that no
  longer repairs invalid HTML, and whitespace between inline elements collapsed by default.
  `astro check` does not accept TypeScript 7 yet, so the workspace is on TypeScript 6.
- Created the branch `rebuild` and the workspace: `apps/site`, `packages/strm-ui`,
  `packages/narrative`, `tests`, `docs`. The v1 components, Tailwind, React and Lenis are gone from
  this branch; they remain in the `v1.*` tags. The two v1 content pages moved to `docs/v1-content`
  as the source for phase 3.
- Verified locally on Node 24: type check clean, static build produces one placeholder page.
- Added CI, `CLAUDE.md`, `docs/NOW.md`, this log, three ADRs, milestones for the phases.

- Created the Project board [strm.dev v2](https://github.com/users/waether-the-strm/projects/3) with
  a horizon field (now / next / later), and put the two open phase 1 issues in "now".

- Connected Cloudflare. `wrangler` is a dev dependency of `apps/site`; the Worker `strm-dev` serves
  the static build with no Worker script. Two workflows: `preview.yml` (every pull request and
  `rebuild`, through `wrangler preview`, which is an open beta) and `deploy.yml` (production, only
  from a `v*.*.*` tag). The first preview is live at
  <https://rebuild-strm-dev.mirecki-janek.workers.dev> and carries `X-Robots-Tag: noindex`.
- Two things learned on the way: `wrangler preview` refuses to run without a `previews` block in the
  config, even an empty one; and a step that pipes into `tee` hides a failure unless the step sets
  `shell: bash`, which turns on pipefail. The first preview run was green while deploying nothing.

- Wrote the first agent skill, `session`: how a session starts and ends. The other skills wait for
  the phase that gives them something to describe. First change made through a pull request, which
  also tested the pull request preview.

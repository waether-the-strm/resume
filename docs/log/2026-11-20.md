## What happened

- Read the prototype's brief, test scenarios and scroll model, and the v1 site: two content pages
  (home and `/cv`), a PDF, deploy to GitHub Pages on a `v*.*.*` tag.
- Checked current versions instead of trusting memory. Astro is at 7.4 (v1 runs 4.13). What that
  changes for a new project: Node 22.23 or newer and even majors only, content collections defined
  in `src/content.config.ts` with loaders, Zod 4 from `astro/zod`, a stricter compiler that no
  longer repairs invalid HTML, and whitespace between inline elements collapsed by default.
  `astro check` does not accept TypeScript 7 yet, so the workspace is on TypeScript 6.
- Created the branch `rebuild` and the workspace: `apps/site`, `packages/strm-ui`,
  `packages/narrative`, `tests`, `docs`. The v1 components, Tailwind, React and Lenis are gone from
  this branch; they remain in the `v1.*` tags. The two v1 content pages moved to `docs/v1-content`
  as the source for phase 3.
- Verified locally on Node 24: type check clean, static build produces one placeholder page.
- Added CI, `CLAUDE.md`, `docs/NOW.md`, this log, three ADRs, milestones for the phases.

- Created the Project board [strm.dev v2](https://github.com/users/waether-the-strm/projects/3) with
  a horizon field (now / next / later), and put the two open phase 1 issues in "now".

- Connected Cloudflare. `wrangler` is a dev dependency of `apps/site`; the Worker `strm-dev` serves
  the static build with no Worker script. Two workflows: `preview.yml` (every pull request and
  `rebuild`, through `wrangler preview`, which is an open beta) and `deploy.yml` (production, only
  from a `v*.*.*` tag). The first preview is live at
  <https://rebuild-strm-dev.mirecki-janek.workers.dev> and carries `X-Robots-Tag: noindex`.
- Two things learned on the way: `wrangler preview` refuses to run without a `previews` block in the
  config, even an empty one; and a step that pipes into `tee` hides a failure unless the step sets
  `shell: bash`, which turns on pipefail. The first preview run was green while deploying nothing.

- Wrote the first agent skill, `session`: how a session starts and ends. The other skills wait for
  the phase that gives them something to describe. First change made through a pull request, which
  also tested the pull request preview.

- Started strm-ui. Tokens in three tiers as plain CSS; colours written once with `light-dark()`; a
  motion profile that zeroes the duration roles. The light values are the prototype's. The dark
  palette and the `-text` partners are proposals, waiting for Jan's eyes. The `/ui` page parses the
  token CSS at build time and prints the measured contrast of every colour in both themes, so the
  documentation cannot claim a contrast the CSS does not have.

- Jan merged the token slice with the values as provisional: he tunes them on the assembled page,
  not on swatches. Built the first primitives as plain CSS classes with component tokens: pill,
  tiles, rule, panel with kicker and mark, paths, work. `/ui/primitives` puts them together the way
  the home page will. A white label on the prototype's accent measures under 4.5:1, so a filled
  surface got its own pair, `--accent-fill` and `--on-accent`: a slightly darker red under white in
  light, dark ink on red in dark. Tests now enforce the tier rules on the CSS.

- Started the content layer. Collections with strict schemas for the message, the card and the
  projects; one file per entry and locale; English as the source with a fallback that prints in the
  build. The home page is now the finished look, the card and the work, server-rendered at `/` and
  `/pl/` with no JavaScript beyond the inline theme restore.
- The prototype's language-dependent rules are gone from the start: content marks runs of words with
  roles (`[clear at a glance.]{accent}`), and text renders one word at a time, each word carrying
  its role. Polish one-letter words are tied to the next word at build time.
- Polish did its job on the first render. The Polish headline is four lines where the English is
  two, and on a 390×664 phone the finished look no longer fits the stage: the name line is cut and
  the call is below the fold. The prototype's compact layout for short phones is not ported yet
  either. Both are open (#12, #13).

## Decided (by Jan)

- A pnpm workspace with three packages, so boundaries are enforced by the package manager.
  [ADR 0001](../adr/0001-workspace.md)
- Hosting moves to Cloudflare now, not at the first server-side need.
  [ADR 0002](../adr/0002-hosting.md)
- strm-ui tokens are written as CSS custom properties; no token build step.
  [ADR 0003](../adr/0003-token-source-format.md)
- Four mechanisms are transplanted from jan-ui: signal and text colour pairs, the theme axis, a
  profile as a separate axis, a key binding registry. Nothing else.
  [ADR 0004](../adr/0004-transplants-from-jan-ui.md)
- strm-ui is documented by pages in the site under `/ui`, not by a separate tool.
  [ADR 0005](../adr/0005-strm-ui-documentation.md)
- Content is files in git, edited through pull requests; no CMS for now.
  [ADR 0006](../adr/0006-content-in-git.md)
